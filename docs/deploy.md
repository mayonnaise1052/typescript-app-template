# Cloudflare へのデプロイ

API（Hono）とフロントエンド（ビルドした静的ファイル）を、1 つの Worker としてデプロイします。Cloudflare の無料プランで動かせます。

`npm run deploy` 1 回で、次のすべてが行われます。

1. フロントエンドをビルドする（`apps/web/dist`）
2. 本番の D1 にマイグレーションを適用する
3. `wrangler deploy` で Worker をデプロイする
4. 教材（レッスンと問題）を本番の D1 に同期する（何度実行しても同じ結果になる）

マイグレーションをデプロイより先に行うのは、新しいコードが古いテーブル構造のまま動く時間を作らないためです。そのため、マイグレーションは「古いコードのままでも壊れない」形で書きます（列の追加は可、列の削除や名前の変更は 2 回のデプロイに分ける）。

教材はコードと一緒に Git で管理している「参照用のデータ」なので、デプロイのたびに同期しています。ユーザーの進捗やノートには影響しません。

### 初回だけは `npm run deploy:init`

初回は D1 データベースがまだ存在しないため、マイグレーションを先に実行できません。最初の 1 回だけ、順序の違う `npm run deploy:init` を使います（デプロイで D1 を自動作成 → マイグレーション → 教材の投入）。Workers Builds で初めてデプロイするときは、デプロイ コマンドを一時的に `npm run deploy:init` にし、成功したら `npm run deploy` に戻してください。

## 方法 A: GitHub と連携して自動でデプロイする（Workers Builds）

`main` にプッシュするたびに、Cloudflare が自動でデプロイします。画面の文言は、表示言語や Cloudflare の更新によって多少異なることがあります。

### 1. GitHub: Cloudflare のアプリにリポジトリへのアクセスを許可する

GitHub の「Settings」→「Applications」→「Cloudflare Workers and Pages」→「Configure」を開きます。「Repository access」で「All repositories」を選ぶか、「Only select repositories」でこのリポジトリを追加します。

これがないと、手動ビルドは成功するのに、プッシュしてもビルドが始まりません。

### 2. Cloudflare: リポジトリから Worker を作る

「Workers & Pages」→「作成」→「Git リポジトリをインポート」で、このリポジトリを選び、次のように設定します。

| 項目                | 値                                                                      |
| ------------------- | ----------------------------------------------------------------------- |
| プロジェクト名      | `typescript-app-template`（`apps/api/wrangler.jsonc` の `name` と同じ） |
| 本番ブランチ        | `main`                                                                  |
| ビルド コマンド     | （空のまま）                                                            |
| デプロイ コマンド   | **初回は** `npm run deploy:init`                                        |
| ルート ディレクトリ | `/`                                                                     |
| ビルド変数          | なし                                                                    |

依存パッケージのインストール（`npm ci`）は Cloudflare が自動で行います。Node.js のバージョンは `.nvmrc`（22）が使われます。

### 3. ビルドの詳細設定を確認する

Worker の「設定」→「ビルド」で、次を確認します。

| 項目                             | 設定                                                                   |
| -------------------------------- | ---------------------------------------------------------------------- |
| ブランチ制御: 本番ブランチ       | `main`。プッシュ時の自動ビルドがオンになっていること                   |
| ブランチ制御: 本番以外のブランチ | **オフ**を推奨（下の注意を参照）                                       |
| API トークン                     | 自動で作られるトークンで可。Workers の編集と **D1 の編集**の権限が必要 |

> **注意**: デプロイ コマンドは本番の D1 にマイグレーションを適用します。本番以外のブランチのビルドを有効にして同じコマンドを使うと、作業中のブランチの変更が本番の DB に適用されてしまいます。

### 4. 初回デプロイ後: デプロイ コマンドを切り替える

初回のビルドが成功したら（D1 データベース `typequest` が作られ、テーブルと教材が入ります）、デプロイ コマンドを **`npm run deploy`** に変更します。以後はマイグレーションがデプロイより先に実行されます。

### 5. 動作確認

Worker の「概要」に表示される URL（`https://typescript-app-template.<サブドメイン>.workers.dev`）を開き、「新規登録」からアカウントを作れば完了です。最初から用意されたアカウントはありません。

## 方法 B: 手元の PC からデプロイする

```bash
npx wrangler login       # ブラウザで Cloudflare にログイン
npm run deploy:init      # 初回のみ
npm run deploy           # 2 回目以降
```

## 更新するとき

| 変更した内容  | 必要な作業                                                          |
| ------------- | ------------------------------------------------------------------- |
| コード・教材  | `npm run deploy`（方法 A ならプッシュするだけ）                     |
| DB のスキーマ | `npm run db:generate` でマイグレーションを作ってコミット → デプロイ |

## 仕組み

`apps/api/wrangler.jsonc` の `assets` の設定により、リクエストは次のように振り分けられます。

- `/api/*` → Worker（Hono）が処理
- それ以外 → `apps/web/dist` の静的ファイルを返す。該当するファイルがなければ `index.html`（画面の経路は React Router がブラウザ側で解決するため）

フロントと API が同じオリジンになるので、CORS の設定は不要で、Cookie もそのまま使えます。

D1 の `database_id` を設定ファイルに書いていないのは、初回のデプロイで自動作成させるためです。ローカル開発とテストでは、手元に作られる D1 が使われるので影響はありません。

## 設定値

| 名前              | 用途                                                             | 既定値 |
| ----------------- | ---------------------------------------------------------------- | ------ |
| `ALLOWED_ORIGINS` | 状態を変更するリクエストを許可する追加のオリジン（カンマ区切り） | 空     |

同一オリジンからのリクエストは常に許可されるため、通常は空のままで構いません。ローカル開発では `apps/api/.dev.vars` で `http://localhost:5173`（Vite）を許可しています。

## うまくいかないとき

| 症状                                                     | 原因と対処                                                                                                                                                                                   |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| プッシュしてもビルドが始まらない（手動ビルドは成功する） | Cloudflare の GitHub アプリがリポジトリにアクセスできていない。GitHub の「Settings」→「Applications」→「Cloudflare Workers and Pages」→「Configure」で、このリポジトリへのアクセスを許可する |
| 「クローン作成中」で失敗する                             | 設定したブランチが GitHub に存在しない。ブランチ名を確認する                                                                                                                                 |
| D1 の作成やマイグレーションで権限エラー                  | ビルド トークンに D1 の編集権限がない。「設定」→「ビルド」→「API トークン」で D1 の編集権限を持つトークンを指定する                                                                          |
| Worker の名前が違うという警告                            | `apps/api/wrangler.jsonc` の `name` を、ダッシュボードの Worker 名に合わせる                                                                                                                 |
