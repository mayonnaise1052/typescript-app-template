## 1. 概要

### 1.1 目的

TypeScript を学ぶための Web アプリです。次の 2 つの面を持ちます。

1. **学習アプリ**: レッスンを読み、確認クイズに解答して、進み具合を記録する
2. **教材としてのソースコード**: このリポジトリ自体が、実務的な TypeScript のコード例になっている。各レッスンから、その概念が使われているファイルを案内する

### 1.2 対象の利用者

| 利用者                                  | 始める場所                                      |
| --------------------------------------- | ----------------------------------------------- |
| TypeScript をはじめて学ぶ人             | 第0章「はじめに」                               |
| JavaScript に慣れていて、型を学びたい人 | 第1章「基礎」                                   |
| 実務での使い方を学びたい人              | 第2章以降と、各レッスンの「発展」の参照先コード |

### 1.3 機能の一覧

| 機能                 | 内容                                                       | 必要な状態   |
| -------------------- | ---------------------------------------------------------- | ------------ |
| 利用者登録           | メールアドレス・表示名・パスワードで登録する               | 未ログイン   |
| ログイン・ログアウト | セッション Cookie によるログイン                           | —            |
| ダッシュボード       | 次に学ぶレッスン、学習の統計、章ごとの進み具合、最近の解答 | ログイン済み |
| レッスン             | 一覧、本文、「発展: このアプリでの使われ方」               | ログイン済み |
| 確認クイズ           | 解答・採点・解説の表示。全問正解でレッスン完了             | ログイン済み |
| ノート               | 学習メモの作成・検索・絞り込み・編集・削除                 | ログイン済み |
| パッケージ           | npm パッケージの検索とブックマーク                         | ログイン済み |

## 2. システム構成

### 2.1 全体像

```
ブラウザ
  │  同じオリジン（https://typescript-app-template.m8y.workers.dev）
  ▼
Cloudflare Workers（1 つの Worker）
  ├─ /api/* 以外 … 静的ファイル（apps/web をビルドしたもの）。存在しないパスは index.html（SPA）
  └─ /api/*     … API（Hono）
                   ├─ D1（データベース、東アジアに配置: typequest-apac）
                   ├─ Rate Limiting バインディング（レート制限の第 1 段）
                   └─ npm レジストリ（外部 API、パッケージ検索のみ）
```

### 2.2 リポジトリの構成

npm workspaces によるモノレポです。

| パス              | 役割                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------- |
| `packages/shared` | フロントと API で共有するもの（Zod スキーマ、エラーコード、Result 型、Branded Types） |
| `apps/api`        | API。Hono、Drizzle ORM、D1。教材（`src/content`）もここにある                         |
| `apps/web`        | フロントエンド。React、TanStack Router、TanStack Query、React Hook Form、shadcn/ui    |
| `e2e`             | Playwright による E2E テスト                                                          |
| `scripts`         | 開発用の補助スクリプト（CSP のハッシュの検査など）                                    |

### 2.3 主な技術

| 区分           | 技術                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------- |
| 言語           | TypeScript（`strict`、`noUncheckedIndexedAccess` などを有効化）                                      |
| API            | Hono（型付き RPC クライアント `hc` でフロントから呼ぶ）、Drizzle ORM、Zod 4                          |
| フロントエンド | React 19（React Compiler）、Vite、TanStack Router（ファイルベース）、TanStack Query、React Hook Form |
| 見た目         | Tailwind CSS v4、shadcn/ui（Base UI 版）、sonner（通知）                                             |
| 実行環境       | Cloudflare Workers、D1、Workers Static Assets、Rate Limiting バインディング                          |
| テスト         | Vitest（API は workerd 上、Web は Browser Mode）、Playwright                                         |

## 3. 画面

### 3.1 画面の一覧

| パス                 | 画面                   | 未ログインで開いたとき              | ログイン済みで開いたとき     |
| -------------------- | ---------------------- | ----------------------------------- | ---------------------------- |
| `/login`             | ログイン               | 表示する                            | 戻り先（なければ `/`）へ移動 |
| `/register`          | 利用者登録             | 表示する                            | 戻り先（なければ `/`）へ移動 |
| `/`                  | ダッシュボード         | `/login?redirect=<元の URL>` へ移動 | 表示する                     |
| `/lessons`           | レッスン一覧           | 同上                                | 表示する                     |
| `/lessons/:lessonId` | レッスン               | 同上                                | 表示する                     |
| `/notes`             | ノート                 | 同上                                | 表示する                     |
| `/packages`          | パッケージ             | 同上                                | 表示する                     |
| 上記以外             | ページが見つかりません | —                                   | —                            |

- 戻り先（`redirect`）は、アプリ内のパス（`/` で始まり、`//` で始まらないもの）だけを受け付ける。外部の URL が指定された場合は無視して `/` へ移動する（オープンリダイレクト対策）
- 画面の出し分けは利便性のためのもので、守りの境界ではない。データは必ず API 側で認可する

### 3.2 共通の振る舞い

| 項目           | 内容                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| ヘッダー       | アプリ名、メニュー（ダッシュボード・レッスン・ノート・パッケージ）、表示名、ログアウト |
| 読み込み中     | 画面ごとの読み込み表示を出す                                                           |
| エラー         | 画面の一部で起きたエラーはその場で表示し、メニューから別の画面へ移動できる             |
| 通知           | 保存・削除などの結果を、画面の端に通知（sonner）で表示する                             |
| 表示の切り替え | OS の設定に従ってライト・ダークを切り替える                                            |
| 画面幅         | スマートフォン幅でも横スクロールが出ないこと                                           |
| 先読み         | リンクにマウスを乗せると、移動先のデータを先に読み込む                                 |

### 3.3 ログイン・利用者登録

- 入力の検査は、フロントと API で同じスキーマ（`packages/shared/src/schemas/auth.ts`）を使う
- 入力エラーは項目ごとに表示する
- 登録またはログインに成功すると、戻り先（なければダッシュボード）へ移動する
- ログインに失敗したときは、メールアドレスとパスワードのどちらが違うかを区別せず「メールアドレスまたはパスワードが正しくありません」と表示する

### 3.4 ダッシュボード

| 表示             | 内容                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------- |
| 次のレッスン     | 学習順で最初の未完了レッスン。「学習する」から開ける。すべて完了していればその旨を表示 |
| 完了したレッスン | 完了数 / 全レッスン数                                                                  |
| 正答率           | これまでの全解答の正解数 ÷ 問題数。解答がなければ「—」                                 |
| 連続学習日数     | 4.4 のストリーク                                                                       |
| クイズ解答回数   | クイズを提出した回数                                                                   |
| 章ごとの進み具合 | 章ごとの完了数 / レッスン数（進捗バー）                                                |
| 最近の解答       | 直近 5 件の解答（レッスン名、点数、日時）                                              |

### 3.5 レッスン一覧

- 章ごとにまとめ、学習順に番号を付けて表示する
- 章の見出しに、その章の完了数 / レッスン数を表示する
- 完了したレッスンには「完了」の印を付ける

### 3.6 レッスン

| 部分                         | 内容                                                                                                        |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 見出し                       | 章名、タイトル、概要。完了していれば「完了」の印                                                            |
| 本文                         | 見出し・段落・コード・箇条書き・補足（情報 / 注意）の組み合わせ。`` `...` `` で囲んだ部分はコードとして表示 |
| 発展: このアプリでの使われ方 | このリポジトリ内の参照先ファイルと説明。**初期状態では閉じている**                                          |
| 確認クイズ                   | 4.3 のクイズ                                                                                                |
| 前後のレッスン               | 前のレッスン・次のレッスンへのリンク                                                                        |

- 別のレッスンへ移動したときは、クイズの入力や結果を引き継がず、ページの先頭から表示する
- 存在しないレッスンを開いた場合は、エラーを表示する

### 3.7 ノート

- 一覧は更新日時の新しい順に表示し、ページ送りができる
- キーワード（タイトルと本文の部分一致）と、関連するレッスンで絞り込める
- 検索条件・ページ番号は URL に保持する（再読み込みや共有で同じ表示になる）。不正な値は既定値として扱う
- 作成・編集はフォームで行い、関連するレッスンは任意で選べる
- 削除する前に確認ダイアログを表示する

### 3.8 パッケージ

- npm のパッケージを名前で検索し、名前・最新版・説明を表示する
- 検索結果からブックマークに追加でき、ブックマークの一覧から削除できる

## 4. 学習の仕組み

### 4.1 教材の構成

教材は `apps/api/src/content/` に TypeScript のデータとして書き、デプロイのたびに D1 へ投入する（4.5）。

| 章             | ID             | レッスン数 | 内容                                                                                                                 |
| -------------- | -------------- | ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 第0章 はじめに | `intro`        | 2          | TypeScript とは、このアプリで使う JavaScript のおさらい                                                              |
| 第1章 基礎     | `basics`       | 6          | 基本の型と型推論、配列とタプル、オブジェクト型、関数、ユニオン型とリテラル型、null と絞り込みの基本                  |
| 第2章 中級     | `intermediate` | 6          | 型の絞り込みと型ガード、判別可能ユニオン、ジェネリクス、ユーティリティ型、unknown・any・never、as const と satisfies |
| 第3章 上級     | `advanced`     | 5          | keyof・typeof、Mapped Types、条件型と infer、テンプレートリテラル型、Branded Types                                   |
| 第4章 実務     | `practical`    | 4          | Zod、async/await と Result 型、モジュールと tsconfig、テスト                                                         |
| 合計           |                | 23         | 問題は 61 問                                                                                                         |

教材を書くときの決まり（`apps/api/src/content/content.test.ts` で一部を自動検査）:

| 決まり                                                                                                                                    | 検査                 |
| ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| レッスン ID は英小文字・数字・ハイフン（`^[a-z0-9-]{1,64}$`）で、重複しない。**一度公開した ID は変えない**（学習記録が ID に紐付くため） | 自動                 |
| すべての章に 1 つ以上のレッスンがあり、章の順に並ぶ。先頭は第0章                                                                          | 自動                 |
| 各レッスンに問題が 2 問以上、第0章・第1章は 3 問以上ある                                                                                  | 自動                 |
| 各レッスンに「発展」の参照先が 1 つ以上あり、参照先のファイルが実在する                                                                   | 自動（教材の投入時） |
| 正解の番号が選択肢の範囲に収まっている                                                                                                    | 自動                 |
| 第0章・第1章では、そのレッスンまでに習った書き方だけを使う（仕様書 0005 の 2.3）                                                          | 人が確認             |

### 4.2 問題の種類

| 種類     | `kind`            | 解答のしかた         | 正解の条件                                                                                                                             |
| -------- | ----------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 単一選択 | `single-choice`   | 選択肢から 1 つ選ぶ  | 正解の番号と一致                                                                                                                       |
| 複数選択 | `multiple-choice` | 選択肢からすべて選ぶ | 選んだ番号の集合が正解の集合と完全に一致                                                                                               |
| 穴埋め   | `fill-blank`      | 空欄に文字を入力する | 正規化した入力が、正解の候補のどれかと一致。正規化: 前後の空白を除く、末尾の `;` を除く、連続する空白を 1 つにする、英字を小文字にする |

問題にはコード例を添えられる。

### 4.3 確認クイズ

- レッスンを開いたとき、API は**正解と解説を送らない**（画面のコードを読んでも答えが分からないようにする）
- 解答を提出すると、API が採点し、問題ごとの正誤・正解・解説を返す
- **全問正解で合格**し、そのレッスンが完了になる。一度完了したレッスンは、後で間違えても完了のまま
- 不合格でも、何度でも解き直せる
- 解答はすべて記録する（4.4 の統計に使う）

### 4.4 進み具合の集計

| 値               | 計算                                                                                                                                        |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 完了したレッスン | 合格したことのあるレッスンの数                                                                                                              |
| 章ごとの進み具合 | 章ごとの完了数 / レッスン数                                                                                                                 |
| 正答率           | 全解答の正解数の合計 ÷ 問題数の合計（0〜1）。解答がなければ `null`                                                                          |
| 連続学習日数     | 今日まで（今日まだ解答していなければ昨日まで）、解答した日が続いている日数。日の区切りは日本時間（UTC+9）。昨日も今日も解答していなければ 0 |
| 最近の解答       | 直近 5 件の解答（レッスン、点数、日時）                                                                                                     |

### 4.5 教材の投入

- デプロイのたびに、教材から SQL を生成して D1 に投入する（`npm run deploy` の中で実行）
- レッスンは ID で「あれば更新、なければ追加」する。教材から消したレッスンは削除する（関連する進捗も一緒に消える）
- 問題はすべて入れ直す。問題 ID は `<レッスン ID>-q<番号>` で自動で振る
- 投入する前に、教材をスキーマで検査する。不正があれば投入を中止する

## 5. API

### 5.1 共通事項

| 項目               | 内容                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| ベースパス         | `/api`                                                                                                                                |
| 形式               | JSON（リクエスト・レスポンスとも）                                                                                                    |
| 認証               | セッション Cookie（6.1）。「要」の API は未ログインなら 401                                                                           |
| 入力の検査         | 共有の Zod スキーマ（`packages/shared/src/schemas/`）で検査し、不正なら 400                                                           |
| リクエストの大きさ | 本文は 64 KiB まで。超えたら 413                                                                                                      |
| キャッシュ         | すべての応答に `Cache-Control: no-store`                                                                                              |
| CSRF 対策          | 状態を変えるリクエスト（GET・HEAD・OPTIONS 以外）は、`Origin` が同じオリジンか許可リスト（`ALLOWED_ORIGINS`）にある場合だけ受け付ける |

エラーの応答は、すべて次の形です。

```json
{ "error": { "code": "VALIDATION_ERROR", "message": "…", "details": { "email": ["…"] } } }
```

| コード                   | HTTP | 主な場面                                             |
| ------------------------ | ---- | ---------------------------------------------------- |
| `VALIDATION_ERROR`       | 400  | 入力が不正。`details` に項目ごとのメッセージ         |
| `UNAUTHENTICATED`        | 401  | 未ログイン、セッション切れ、ログイン失敗             |
| `FORBIDDEN`              | 403  | 許可されていないオリジンからの状態変更               |
| `NOT_FOUND`              | 404  | 存在しない（または他人の）データ、存在しない API     |
| `CONFLICT`               | 409  | メールアドレスの重複、件数の上限、ブックマークの重複 |
| `RATE_LIMITED`           | 429  | レート制限（`Retry-After` ヘッダーに待つ秒数）       |
| `EXTERNAL_SERVICE_ERROR` | 502  | npm レジストリから取得できない                       |
| `INTERNAL_ERROR`         | 500  | 想定外のエラー（詳細は返さず、ログに記録）           |

### 5.2 エンドポイントの一覧

| メソッド | パス                                  | 認証 | レート制限     | 成功時 | 内容                                                                       |
| -------- | ------------------------------------- | ---- | -------------- | ------ | -------------------------------------------------------------------------- |
| GET      | `/api/health`                         | 不要 | —              | 200    | 稼働確認 `{ status: "ok" }`                                                |
| POST     | `/api/auth/register`                  | 不要 | 認証           | 201    | 利用者登録してログインする `{ user }`                                      |
| POST     | `/api/auth/login`                     | 不要 | 認証           | 200    | ログインする `{ user }`                                                    |
| POST     | `/api/auth/logout`                    | 不要 | —              | 200    | ログアウトする `{ ok: true }`                                              |
| GET      | `/api/auth/me`                        | 要   | —              | 200    | ログイン中の利用者 `{ user }`                                              |
| GET      | `/api/lessons`                        | 要   | —              | 200    | レッスンの一覧（学習順、完了の有無つき）                                   |
| GET      | `/api/lessons/:lessonId`              | 要   | —              | 200    | レッスンの詳細（本文・参照先・問題・前後のレッスン）。正解と解説は含まない |
| POST     | `/api/lessons/:lessonId/quiz`         | 要   | —              | 200    | 解答を採点する `{ result }`                                                |
| GET      | `/api/progress`                       | 要   | —              | 200    | 進み具合の集計 `{ progress }`                                              |
| GET      | `/api/notes`                          | 要   | —              | 200    | ノートの一覧（`page`・`pageSize`・`q`・`lessonId`）                        |
| POST     | `/api/notes`                          | 要   | —              | 201    | ノートを作成する `{ note }`                                                |
| GET      | `/api/notes/:noteId`                  | 要   | —              | 200    | ノートを取得する `{ note }`                                                |
| PATCH    | `/api/notes/:noteId`                  | 要   | —              | 200    | ノートを部分更新する `{ note }`                                            |
| DELETE   | `/api/notes/:noteId`                  | 要   | —              | 200    | ノートを削除する `{ ok: true }`                                            |
| GET      | `/api/packages/search?q=`             | 要   | パッケージ検索 | 200    | npm パッケージを検索する `{ packages }`                                    |
| GET      | `/api/packages/bookmarks`             | 要   | —              | 200    | ブックマークの一覧 `{ bookmarks }`                                         |
| POST     | `/api/packages/bookmarks`             | 要   | —              | 201    | ブックマークを追加する `{ bookmark }`                                      |
| DELETE   | `/api/packages/bookmarks/:bookmarkId` | 要   | —              | 200    | ブックマークを削除する `{ ok: true }`                                      |

各エンドポイントの入出力の型は、`packages/shared/src/schemas/` のスキーマが正です。フロントは Hono の RPC クライアントを使うので、API の型の変更はフロントの型チェックで検出されます。

### 5.3 入力の制約と業務ルール

**利用者**

| 項目           | 制約                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| メールアドレス | 前後の空白を除き、小文字にしてから検査。メールアドレスの形式、254 文字以内。重複不可 |
| 表示名         | 前後の空白を除いて 1〜40 文字                                                        |
| パスワード     | 10〜128 文字                                                                         |

**クイズ**

| 項目       | 制約                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| 解答の数   | 20 件まで。解答のない問題は不正解として扱う。同じ問題への解答が複数あれば最後のものを使う |
| 選択肢番号 | 0〜20                                                                                     |
| 穴埋め     | 200 文字まで                                                                              |

**ノート**

| 項目             | 制約                                                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| タイトル         | 前後の空白を除いて 1〜100 文字                                                                                                   |
| 本文             | 前後の空白を除いて 1〜5000 文字                                                                                                  |
| 関連するレッスン | 任意（`null` 可）。存在しないレッスンを指定すると 400（項目 `lessonId` のエラー）                                                |
| 件数             | 1 人 1000 件まで（超えると 409）                                                                                                 |
| 一覧             | 更新日時の新しい順。`pageSize` は 1〜50（既定 10）。`q` は 100 文字まで、タイトルと本文の部分一致（`%` と `_` は文字として扱う） |
| 更新             | 1 つ以上の項目を指定する                                                                                                         |

**パッケージ**

| 項目            | 制約                                                                                      |
| --------------- | ----------------------------------------------------------------------------------------- |
| 検索語          | 前後の空白を除いて 1〜100 文字                                                            |
| 検索結果        | 最大 10 件。npm レジストリへの問い合わせは 5 秒で打ち切る                                 |
| キャッシュ      | 同じ検索語（大文字・小文字を区別しない）の結果を 10 分間 D1 に保存し、外部 API を呼ばない |
| 外部 API の応答 | スキーマで検査し、形が合わないものは使わない                                              |
| ブックマーク    | 1 人 100 件まで。同じパッケージは重複して登録できない（409）                              |

**他人のデータ**: ノート・ブックマーク・進み具合は、すべて利用者ごとに分ける。他人のデータの ID を指定しても、存在を明かさないよう 404 を返す。

## 6. セキュリティ

詳細と理由は `docs/security.md` を参照。

### 6.1 認証とセッション

| 項目             | 内容                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| パスワードの保存 | PBKDF2-SHA256、10 万回、利用者ごとのソルト。反復回数をハッシュと一緒に保存する（Workers の WebCrypto の上限による） |
| セッション       | ランダムなトークンを Cookie で渡し、DB にはトークンのハッシュだけを保存する                                         |
| 有効期間         | 7 日。期限切れのセッションは使えず、削除する                                                                        |
| Cookie           | `HttpOnly`、`Secure`（HTTPS のとき）、`SameSite=Lax`、`Path=/`                                                      |
| ログアウト       | DB のセッションを削除し、Cookie を消す                                                                              |

### 6.2 レート制限

接続元の IP アドレス（`CF-Connecting-IP`）ごとに、二段構えで数える（仕様書 0004）。

| 対象           | 第 1 段（Rate Limiting バインディング） | 第 2 段（D1 のカウンター） |
| -------------- | --------------------------------------- | -------------------------- |
| 登録・ログイン | 60 秒に 20 回                           | 60 秒に 10 回              |
| パッケージ検索 | 60 秒に 60 回                           | 60 秒に 30 回              |

- 第 1 段は Cloudflare の拠点ごとのおおよその数で、大量のリクエストを D1 に届く前に止める。第 1 段で止めたリクエストは D1 に書き込まない
- 第 2 段は拠点をまたいで正確に数える
- どちらで止めても、同じ 429 と `Retry-After` を返す

### 6.3 レスポンスヘッダー

| 対象                 | ヘッダー                                                                                                                                                                                                                                                                      |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画面（静的ファイル） | `apps/web/public/_headers`。CSP（`script-src 'self'`、`style-src 'self'` と sonner の CSS のハッシュ 2 つ、`frame-ancestors 'none'` など。`'unsafe-inline'` は使わない）、`X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy` |
| API                  | `secureHeaders`（CSP は `default-src 'none'`）と `Cache-Control: no-store`                                                                                                                                                                                                    |

sonner の CSS のハッシュは `npm run csp:check` で検査する（CI でも実行）。

### 6.4 その他

- SQL は Drizzle のプレースホルダで組み立て、文字列を埋め込まない
- 教材の本文は HTML ではなく構造化データで持ち、画面側で描画する（XSS 対策）
- 想定外のエラーの詳細は利用者に返さない

## 7. データ

D1（SQLite 互換）。定義は `apps/api/src/db/schema.ts`、マイグレーションは `apps/api/migrations/`。

| テーブル            | 内容                            | 主な列                                                                                  |
| ------------------- | ------------------------------- | --------------------------------------------------------------------------------------- |
| `users`             | 利用者                          | `id`、`email`（一意）、`display_name`、`password_hash`、`created_at`                    |
| `sessions`          | ログインのセッション            | `token_hash`（主キー）、`user_id`、`expires_at`                                         |
| `lessons`           | レッスン（教材から投入）        | `id`、`chapter_id`、`position`、`title`、`summary`、`body`（JSON）、`code_refs`（JSON） |
| `questions`         | 問題（教材から投入）            | `id`、`lesson_id`、`position`、`data`（JSON、正解と解説を含む）                         |
| `lesson_progress`   | レッスンの完了                  | `user_id`、`lesson_id`、完了日時                                                        |
| `quiz_attempts`     | クイズの解答の記録              | `id`、`user_id`、`lesson_id`、`score`、`total`、解答日時                                |
| `notes`             | ノート                          | `id`、`user_id`、`lesson_id`（任意）、`title`、`body`、作成・更新日時                   |
| `package_bookmarks` | ブックマーク                    | `id`、`user_id`、`name`、`version`、`description`、作成日時                             |
| `rate_limits`       | レート制限の第 2 段のカウンター | `key`、`window_start`、`count`                                                          |
| `api_cache`         | 外部 API の応答のキャッシュ     | `key`、`value`、有効期限                                                                |

- 利用者を削除すると、その利用者のセッション・進捗・解答・ノート・ブックマークも削除される（`ON DELETE CASCADE`）
- レッスンを教材から削除すると、そのレッスンの問題・進捗・解答も削除される。ノートは残り、関連するレッスンが外れる（`ON DELETE SET NULL`）
- ID は、利用者・ノート・ブックマークが UUID、レッスンは教材で決めた文字列、問題は `<レッスン ID>-q<番号>`

## 8. 開発と運用

詳細は `README.md`、`docs/testing.md`、`docs/deploy.md` を参照。

### 8.1 品質の確認

| 段階                 | 内容                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------- |
| 開発中               | `npm run dev` で、API・画面と一緒に型チェックを常時実行                                 |
| コミット時           | Git の pre-commit フックで型チェック（`npm run typecheck`）。失敗するとコミットできない |
| `npm run check`      | 整形・lint・CSP のハッシュの検査・型チェック・全テスト                                  |
| CI（GitHub Actions） | プルリクエストごとに `npm run check` 相当と E2E テスト                                  |
| デプロイ時           | `npm run deploy` の最初に型チェック                                                     |

| テスト     | 場所・方法                                                                     |
| ---------- | ------------------------------------------------------------------------------ |
| 共有コード | `packages/shared`。スキーマの単体テストと型のテスト（`expectTypeOf`）          |
| API        | `apps/api`。Workers ランタイム（workerd）の中で、D1 を含めて実行する結合テスト |
| 画面       | `apps/web`。Vitest Browser Mode（Chromium）と MSW による部品・画面のテスト     |
| E2E        | `e2e`。Playwright で、実際のブラウザから API・D1 まで通す                      |

### 8.2 デプロイ

- `main` ブランチに取り込むと、Cloudflare Workers Builds が自動でデプロイする
- デプロイの手順（`npm run deploy`）: 型チェック → 画面のビルド → D1 のマイグレーション → Worker のデプロイ → 教材の投入
- 作業はブランチで行い、プルリクエストで CI の成功を確認してから `main` に取り込む

### 8.3 設定値

| 名前                          | 種類                         | 内容                                                         |
| ----------------------------- | ---------------------------- | ------------------------------------------------------------ |
| `DB`                          | D1 バインディング            | データベース `typequest-apac`                                |
| `AUTH_RATE_LIMITER`           | Rate Limiting バインディング | 登録・ログインのレート制限（第 1 段）                        |
| `PACKAGE_SEARCH_RATE_LIMITER` | Rate Limiting バインディング | パッケージ検索のレート制限（第 1 段）                        |
| `ALLOWED_ORIGINS`             | 環境変数                     | 状態の変更を許可する追加のオリジン（カンマ区切り）。本番は空 |
