## 1. 背景と目的

仕様書 0002 では、開発環境から shadcn/ui の配布元（`ui.shadcn.com`）に接続できなかったため、部品を同じ構成で書き起こしました。その後、配布元への接続が許可されたため、指示どおり shadcn/ui の公式 CLI で部品を取り込み直します。

作業は 2 段階に分けます。

| 段階      | 内容                                                                  | 理由                                                        |
| --------- | --------------------------------------------------------------------- | ----------------------------------------------------------- |
| 第 1 段階 | 通知以外の部品を、公式 CLI で取り込んだ部品に置き換える               | 見た目と使い方の変更だけで、セキュリティ設定に影響しない    |
| 第 2 段階 | 通知を shadcn/ui 標準の sonner に切り替え、CSP を必要な分だけ変更する | セキュリティ設定の変更を伴うため、第 1 段階と分けて確認する |

## 2. 第 1 段階: 公式部品への置き換え

### 2.1 方針

| 項目            | 内容                                                                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 初期化          | `npx shadcn init --base base --template vite --preset nova`（土台は Base UI、見た目のプリセットは nova）                                                           |
| 取り込む部品    | button / input / label / textarea / card / badge / progress / radio-group / checkbox / alert-dialog / native-select / field（field が使う separator も自動で入る） |
| 部品の置き場所  | `apps/web/src/components/ui/`。設定は `apps/web/components.json`                                                                                                   |
| import の書き方 | 部品同士は `@/components/ui/...` で参照する。そのため `@/*` → `src/*` の別名を tsconfig と Vite に設定する                                                         |
| 配色            | 色の名前は shadcn/ui の決まりに合わせ、値はこのアプリの青基調の配色を使う                                                                                          |
| ダークモード    | 従来どおり OS の設定に従う。部品に書かれた `dark:` の指定も OS の設定で切り替わるようにする（`@custom-variant dark`）                                              |
| フォント        | CLI が入れた Geist（英数字用）を使い、日本語は従来の日本語フォントで表示する                                                                                       |

| 部品           | 変更                                                                                                    |

| Badge          | 「完了」の表示用に `success` の種類を追加する（公式の部品はリポジトリ内のコードなので、追加してよい）   |

## 3. 第 2 段階: 通知を sonner に切り替える

### 3.1 方針

- 通知を shadcn/ui 標準の sonner（`npx shadcn add sonner`）に切り替える
- sonner は読み込み時に `<style>` 要素を追加するため、CSP の `style-src 'self'` でブロックされる（仕様書 0002 の 8 章の 1）
- CSP は、`'unsafe-inline'` で全面的に許可するのではなく、**sonner が追加する CSS だけをハッシュで許可する**

### 3.2 CSP の変え方の比較と判断

| 方法                                    | 内容                                                       | 位置付け                         | 採否       |
| --------------------------------------- | ---------------------------------------------------------- | -------------------------------- | ---------- |
| `style-src` に `'unsafe-inline'` を足す | どんなスタイルの埋め込みも許可する                         | 実務で一般的                     | 採用しない |
| sonner の CSS だけをハッシュで許可する  | sonner が追加する CSS の内容の指紋（SHA-256）を CSP に書く | セキュリティの推奨（厳格な CSP） | **採用**   |

判断の理由: このアプリはセキュリティの学習教材も兼ねており、厳格な設定を保つ方針とする。スクリプト（`script-src`）は従来どおりインラインを一切許可しない。

### 3.3 運用上の注意

- sonner を更新して CSS が変わると、ハッシュが合わなくなり通知の見た目が崩れる
- E2E テスト（コンソールに CSP 違反が出ないことの検査）がこれを検出するので、CI で気付ける
- ハッシュを計算し直す手順をドキュメントに書く

### 3.4 受け入れ条件

- [x] 通知が sonner で表示される
- [x] CSP に `'unsafe-inline'` が含まれない
- [x] 本番のサイトで CSP 違反がコンソールに出ない
- [x] ハッシュの計算し直し方が `docs/security.md` に書かれている

### 3.5 実装

| 項目   | 内容                                                                                                                                                                                     |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 部品   | `npx shadcn add sonner` で取り込んだ `components/ui/sonner.tsx`。Base UI の Toast（`components/ui/toast.tsx`）は削除                                                                     |
| テーマ | 標準の部品は `next-themes` でテーマを読む。このアプリはテーマを切り替える部品を置いていないので、通知は OS の設定に従って明暗が切り替わる                                                |
| CSP    | `style-src 'self'` に、sonner が追加する空の `<style>` と CSS 本体の 2 つのハッシュを追加                                                                                                |
| 検査   | `scripts/check-csp-hashes.mjs`。インストール済みの sonner の配布ファイルから CSS を取り出してハッシュを計算し、`_headers` と比べる。`--write` で書き換える。`npm run check` と CI に追加 |

### 3.6 検証結果（ローカル）

| 確認項目                              | 結果                                                                                              |
| ------------------------------------- | ------------------------------------------------------------------------------------------------- |
| スクリプトで計算したハッシュ          | 仕様書 0002 の作業中にブラウザが CSP 違反として報告した値と一致した（計算方法が正しいことの確認） |
| `npm run check`（`csp:check` を含む） | 成功                                                                                              |
| `npm run test:e2e`                    | 成功。10 件。sonner は読み込み時に CSS を追加するので、CSP 違反の検査に sonner の CSS が含まれる  |
| 検査が働くことの確認                  | CSS 本体のハッシュを一時的に外すと、`csp:check` と E2E の CSP 違反の検査の両方が失敗した          |
| 開発サーバーでの画面確認              | ライト・ダークの両方で通知が sonner の見た目で表示された                                          |

3. 作業ブランチからプルリクエストを作り、CI の成功を確認してから `main` に取り込む
4. Cloudflare のデプロイ完了を確認し、本番のサイトで主要な操作を確認する。確認用のデータは削除する
