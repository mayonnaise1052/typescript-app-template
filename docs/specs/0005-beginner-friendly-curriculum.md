| 状態   | 実装・ローカル確認済み（本番未反映）                                                                            |
| 作成日 | 2026-11-17                                                                                                      |
| 対象   | `apps/api/src/content`（教材）、`packages/shared`（章の定義）、`apps/web`（レッスン画面）、テスト、ドキュメント |

## 1. 背景と目的

実際にアプリを使ったところ、「最初のほうでユニオン型などが出てきて難しい」という感想があった。教材を見直した結果、次の問題が分かった。

| 問題                                 | 内容                                                                                                                                                                                            |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| まだ習っていない内容を先に使っている | ユニオン型は第1章の 5 番目で習うが、2 番目の「関数の型」の本文と問題で `number \| undefined` を使っている。ほかにもリテラル型、`Array<string>`、型の絞り込み、tsconfig の設定項目が先に出てくる |
| JavaScript の知識を前提にしている    | アロー関数・分割代入・`?.`・`??` などを説明なしで使っている。前提であることもどこにも書いていない                                                                                               |
| 1 レッスンの内容が多く、練習が少ない | 1 レッスンに 3〜4 個の新しい概念があるのに、問題は 2 問だけ                                                                                                                                     |
| 「関連するコード」が初心者には重い   | Worker の設定や認証の処理など、実務のコードへの案内が、本文と同じ重みで表示されている                                                                                                           |

TypeScript の初心者が、つまずかずに第1章を終えられるようにする。第2章以降の中級・上級・実務の内容は残す。

## 2. 方針

### 2.1 第0章「はじめに」を追加する

| ID                     | タイトル                               | 内容                                                                                                                                   |
| ---------------------- | -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `what-is-typescript`   | TypeScript とは                        | JavaScript との関係、型の検査は実行の前に行われること、型は実行時に消えること、試す場所（公式の Playground）、エラーメッセージの読み方 |
| `javascript-refresher` | このアプリで使う JavaScript のおさらい | `const` と `let`、アロー関数、テンプレート文字列、分割代入、スプレッド構文、`map` と `filter`、`?.` と `??`。型は使わない              |

### 2.2 第1章を組み直す

| 順  | ID                           | タイトル                         | 主な内容                                                                                                            |
| --- | ---------------------------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 1   | `types-and-inference`        | 基本の型と型推論                 | `string` / `number` / `boolean`、型注釈、型推論、エラーになる代入                                                   |
| 2   | `arrays-and-tuples`          | 配列とタプル                     | `number[]`、配列の型推論、`readonly` な配列、タプル                                                                 |
| 3   | `objects-and-interfaces`     | オブジェクト型と interface       | `type` での名前付け、省略できるプロパティ、`readonly`、`interface`、構造的型付け                                    |
| 4   | `functions`                  | 関数の型                         | 引数と戻り値、`void`、既定値、省略できる引数、関数の型                                                              |
| 5   | `unions-and-literals`        | ユニオン型とリテラル型           | `\|` によるユニオン、リテラル型、`const` で宣言した値の型、文字列リテラルのユニオン                                 |
| 6   | `null-and-narrowing`（新規） | null・undefined と絞り込みの基本 | `string \| null`、`if` と `typeof` による絞り込み、`?.` と `??`、省略できるプロパティと配列の要素に付く `undefined` |

- 「関数の型」と「オブジェクト型」は順番を入れ替える。関数の例でオブジェクトを返すことがあるため
- 型の絞り込みの基本は、第2章から第1章へ前倒しする。ユニオンを習った直後に「どう安全に使うか」まで学べるようにするため。第2章の「型の絞り込みと型ガード」は、`instanceof`・`in`・自作の型ガードに重点を置き、冒頭で第1章を振り返る
- レッスン ID は変えない（学習の記録は ID で管理しているため）

### 2.3 各レッスンで使ってよい書き方

第0章と第1章の本文・問題では、**そのレッスンまでに習った書き方だけ**を使う。

| レッスン               | 新しく使えるようになる書き方                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------- |
| TypeScript とは        | `: number` のような型注釈（見た目の紹介のみ）                                                         |
| JavaScript のおさらい  | `const`・`let`、アロー関数、テンプレート文字列、分割代入、スプレッド構文、`map`・`filter`、`?.`・`??` |
| 基本の型と型推論       | `string`・`number`・`boolean` の型注釈                                                                |
| 配列とタプル           | `型[]`、`readonly 型[]`、`[型, 型]`                                                                   |
| オブジェクト型         | `type 名前 = { ... }`、`?:`、`readonly`、`interface`                                                  |
| 関数の型               | 引数と戻り値の型、`void`、既定値、`?` の付いた引数、`(a: 型) => 型`                                   |
| ユニオン型とリテラル型 | `\|`、リテラル型                                                                                      |
| null と絞り込みの基本  | `null`・`undefined` を含むユニオン、`if (x !== null)`、`typeof`                                       |

次のものは第1章では使わない: ジェネリクスの書き方（`Array<string>` など）、tsconfig の設定項目の詳しい説明（`noUncheckedIndexedAccess` は 6 番目で「このアプリの設定」として結果だけ紹介する）、`bigint`・`symbol`。

### 2.4 問題を増やす

- 第0章と第1章は、1 レッスンにつき 3〜4 問にする
- 「エラーになる行を選ぶ」問題を入れ、エディタで型の検査を受ける感覚に近づける

### 2.5 「関連するコード」を発展扱いにする

- レッスン画面の見出しを「発展: このアプリでの使われ方」に変える
- 初期状態では閉じておき（`<details>`）、開くと一覧が見える。初心者は読み飛ばしてよいことを説明に書く

### 2.6 章の表示

| 章 ID           | 表示           |
| --------------- | -------------- |
| `intro`（新規） | 第0章 はじめに |
| `basics`        | 第1章 基礎     |
| 以降            | 変更なし       |

## 3. 既存のデータへの影響

| 項目           | 影響                                                                     |
| -------------- | ------------------------------------------------------------------------ |
| 学習の記録     | レッスン ID を変えないので、合格の記録は残る                             |
| 問題           | 教材の投入時に入れ直される（既存の仕組み）。第1章の問題の内容が変わる    |
| 進み具合の割合 | レッスンが 20 件から 23 件に増えるため、割合は少し下がる                 |
| データベース   | 章 ID は文字列で保存しており、値の制約はないため、マイグレーションは不要 |

## 4. テスト

| 確認すること                                           | 方法                                     |
| ------------------------------------------------------ | ---------------------------------------- |
| 全レッスンがスキーマに合い、教材どおりに解くと合格する | 既存の教材テストと API テスト            |
| 第0章・第1章の各レッスンに 3 問以上ある                | 教材テストに追加                         |
| 章が 5 つになり、第0章から順に並ぶ                     | 教材テスト・型のテスト・API テストを更新 |
| 「関連するコード」が閉じた状態で表示され、開ける       | E2E テスト                               |
| 最初のレッスンから学習を始められる                     | E2E テストを新しい教材に合わせて更新     |

「まだ習っていない書き方を使っていないか」は機械では確かめにくいため、2.3 の表に沿って人が確認する。
